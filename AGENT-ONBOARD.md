# Інструкція агентові: підключи себе сам

Поклади цей файл туди, звідки твій агент читає правила — `CLAUDE.md`,
`AGENTS.md`, правила Cursor, системний припис. Далі агент робить усе сам.

Тут **немає опису форматів** жодного агента, і це навмисно. Формати
змінюються, агентів більшає, і коннектор під кожного — робота без кінця.
Натомість є алгоритм самознаходження і ворота, які відрізняють
«підключився» від «написав, ніби підключився».

---

## Що від тебе треба

Віддати послідовність записів. Один запис — одна подія розмови.

```text
repo_id      відбиток НАБОРУ кореневих комітів (рахує ядро, не ти)
session_id   стабільний у межах сесії
event_id     ВЛАСНИЙ ідентифікатор події у твоєму журналі, якщо він є
turn         порядковий номер події в сесії, не спадає
ts           час UTC рядком
actor        user | agent | tool
kind         message | tool_call | compact_summary
paths[]      шляхи файлів, ВІДНОСНІ від кореня репозиторію
```

**Про `event_id` окремо.** Якщо твій журнал дає події власний
ідентифікатор (uuid, id, рядок-ключ) — віддай його обовʼязково. На ньому
тримається злиття сховищ між пристроями: без нього адресою стає час і
набір шляхів, і дві різні події з однаковим часом склеяться. Порядковий
номер для цього не годиться — він залежить від того, звідки читали файл.

Більше нічого. Вміст повідомлень не потрібен: він дорогий, містить
секрети і не переноситься між агентами.

---

## Алгоритм

### 1. Знайди власне сховище сесій

Не вгадуй. Перевір, у такому порядку:

```text
змінні середовища свого хоста
теку конфігурації (~/.<твій агент>/, %APPDATA%\<твій агент>\)
власну документацію: «де зберігається історія розмов»
```

### 2. ДОВЕДИ, що це ТВОЇ журнали

Це головний крок, і пропустити його не можна.

```text
візьми рядок, який користувач написав у ЦІЙ розмові
знайди його у файлах, які ти вважаєш своїм сховищем
НЕ знайшов -> сховище не те. Повернись до кроку 1
```

Чому саме так: якщо ти не знайшов журналів, найпростіше — написати
правдоподібний адаптер, який віддає порожнечу або вигадане. Збіг із
реальним рядком користувача робить різницю між «знайшов» і «здається,
знайшов» машинно видимою. Без цього кроку все інше не варте нічого.

### 3. Визнач формат

Прочитай **один** запис. Випиши назви полів. Не читай усе сховище:
воно може бути на гігабайти.

Можливі форми: JSONL, стиснений JSONL, SQLite, своє. Чим розпаковувати —
вирішуй сам; інструмент перевіряє результат, а не спосіб.

### 4. Напиши адаптер

Три речі, більше нічого:

```python
NAME = "<коротке імʼя>"

def discover(root=None) -> list[str]:
    """Усі файли журналів. Порожній список — теж відповідь."""

def read(path, offset=0):
    """Події одного журналу від зміщення. Віддавай словники:
       {session_id, ts, actor, kind, abs_paths, cwd}
       Шляхи тут ще АБСОЛЮТНІ — відносними їх зробить ядро,
       бо лише воно знає корені репозиторіїв."""
```

Зразок — `adapters/claude_code.py`. Він навмисно короткий: якщо адаптер
не вміщується на екран, ти робиш щось не те.

**Чого не роби:** не вигадуй полів, яких у твоєму журналі немає. Лиши
порожнім. Вигадане поле гірше за відсутнє, бо виглядає як дані.

### 5. Прожени ворота

```bash
python cairn.py selftest --store <тека> --adapter <твоє імʼя>
```

Поки це не зелене, адаптера не існує. Ворота відхиляють:

```text
B  discover() не знайшов жодного журналу
C  read() не віддав жодної події
D  поля події відсутні або actor/kind поза переліком
E  шляхи без каталогу — ознака вигаданих даних
F  repo_id різний для того самого репозиторію
```

Що ворота **не** перевіряють і перевірити не можуть: чи твій крок 2
справді виконано. Це на твоїй совісті, і саме тому він описаний першим.

### 6. Проіндексуй

```bash
python cairn.py index --store <тека> --adapter <твоє імʼя>
python cairn.py why   --store <тека> <шлях у репозиторії>
```

## Перевір, що ворота взагалі працюють

Перш ніж вірити зеленому на своєму адаптері, подивись, що вони червоні
на підробках. Вони лежать поруч і призначені саме для цього:

```bash
python cairn.py selftest --store <тека> --adapter _probe_empty      # B
python cairn.py selftest --store <тека> --adapter _probe_noevents   # C
python cairn.py selftest --store <тека> --adapter _probe_badactor   # D
python cairn.py selftest --store <тека> --adapter claude_code       # мусить пройти
```

Перші три мусять дати код виходу 1, останній — 0. Якщо проходить усе,
зламані ворота, а не адаптер.

## Правила, які не обговорюються

```text
ТІЛЬКИ ЧИТАННЯ    журнали не редагувати, не переміщати, не чистити
БЕЗ АБСОЛЮТНИХ    у сховище не потрапляє C:\Users\..., /home/...:
ШЛЯХІВ            інакше воно не переноситься й розкриває чуже
БЕЗ ВМІСТУ        тексти повідомлень за умовчанням не зберігаються
НЕ ВИГАДУВАТИ     немає даних -> порожньо, а не правдоподібно
```

Останнє головне. Сховище причинності, у якому є вигадані записи, гірше
за його відсутність: воно виглядає як доказ.
