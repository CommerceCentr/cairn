# Cairn

> [English](README.md) · [Мандат агенту](MANDATE-AGENT-CAIRN-CAUSAL-HISTORY.md) · [Apache-2.0](LICENSE)

Cairn зберігає причини змін коду для інших агентів і пристроїв. У локальному
сховищі `.cairn` він пов’язує Git-коміти, вузли проєкту, завершені правки
агентів і доступний контекст сесій. Читання та пошук файлів не створюють
причинних подій.

Для контрольного файла `cairn_unified/why.py` є 78 кандидатів правок:
16 мають Git-свідка, 2 — атестовану причину конкретної події, 2 — причину
стану файла, 62 лишаються неприв’язаними. Інший вузол, `ontology.py`, має
одну атестовану причину події. Це **твердження учасників, пов’язані з
перевіреними правками**, а не доказ правильності рішення чи того, хто
виконав `git commit`. Для 17 комітів лише з Git-контекстом Cairn не вигадує
відсутню сесію або мотив.

## Робочий цикл агента

1. Перед правкою прочитай поточний код та історію через `why node`. Якщо
   `freshness.status` дорівнює `stale`, спочатку синхронізуй сховище.
2. Після завершеної правки й до коміту запиши короткий `change note` з
   `why` та `intent`. Codex може знайти посилання на завершений `FileChange`
   через `change codex-events` і додати `session_id` та `event_id` до
   нотатки одного файла. Інші адаптери використовують лише ті докази, які
   справді є в їхніх журналах.
3. Після коміту запусти синхронізацію причинності. Лише унікальний перехід
   вмісту в Git переводить правку в підтверджену історію. Stash і discard
   лишаються кандидатами. Перевір `why node`, `change status`,
   `project doctor` та Git-свідки.
4. Експортуй оновлений приватний пакет для іншого пристрою. Він містить
   записані докази, а не посилання на локальні журнали. Не додавай його до
   публічного Git: там є текст людини й агентів.

[Мандат агенту](MANDATE-AGENT-CAIRN-CAUSAL-HISTORY.md) містить команди й
правила доказу. [Підключення агента](AGENT-ONBOARD.md) описує CLI та MCP.

## Межа релізу

У поточному дереві коду немає машинних абсолютних шляхів. **26 старих
комітів повної Git-історії їх ще містять**, тому повну історію `main` не
очищено для публікації. Для релізу підготовлено чистий source snapshot без
`.git` і `.cairn`. Публікація очищеної повної історії потребує також міграції
Git-ідентичності й доказів Cairn. Приватний пакет не входить до публічного
зрізу коду.
