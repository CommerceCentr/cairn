### Ваш AI-агент забуває все між сесіями. Cairn памʼятає.

Закрили термінал — і завтра агент починає з нуля. Він перечитує ті самі
файли, пропонує те, що ви вчора відкинули, і витрачає токени на
відновлення того, що вже знав. Вікно контексту тим часом займає
археологія, а не ваша задача.

**Cairn зберігає ті розмови й повертає їх тоді, коли вони потрібні.**
Питаєте *«чому цей файл такий?»* — і отримуєте відповідь приблизно за
**300–1 700 токенів** замість **12 000–240 000**, які пішли б на ручне
копання в git.

Проєкт розроблено **за підтримки компанії розробників
[CommerCentr](https://commercentr.com/en)**.

## Проблема однією таблицею

У агента фіксоване вікно контексту. Історію ріжуть із нього першою — не
тому, що вона зайва, а тому, що вона величезна. Виміряно на справжньому
файлі:

| Що довелося б прочитати агентові | Байтів | ≈ токенів |
|---|---:|---:|
| сам файл | 646 713 | **162 000** |
| його 166 повідомлень комітів (`git log`) | 169 698 | **42 000** |
| повні діфи (`git log -p`) — де живе прибрана проза | 959 030 | **240 000** |

Третій рядок і є проблемою: місце, де пояснення **справді лежить**, не
влазить у жодне поширене вікно контексту. Тому агент гортає по
діагоналі, вгадує або наново виводить рішення, яке вже ухвалили й
відкотили.

На одному класі ми нарахували **26 правок за чотири місяці**,
щонайменше **чотири** з них лагодили той самий дефект. Жодна не
записала причини. Пʼята правка була б пʼятою латкою.

*(Токени всюди оцінені як символи ÷ 4 і позначені як оцінка; байти —
виміряні.)*

## Як це працює

```text
   журнали агентських сесій --+
                              |
   git-історія ---------------+--->  переносне сховище  --->  why <файл>
                                     JSONL, 7.2 МБ            why --node <вузол>
                                     локальне, ваше           bind --zone <зона>
```

```bash
python cairn.py index --store ./store                   # зібрати
python cairn.py why   --store ./store <шлях або вузол>  # спитати
python cairn.py merge --store ./store --other <чуже>    # синхронізувати
```

**Лише стандартна бібліотека Python.** Ні бази, ні демона, ні хмари, ні
формату, який через рік ніхто не відкриє.

Усе тримається на трьох ідеях:

```text
1  АДРЕСУВАТИ ЗМІСТ, А НЕ ПОЗИЦІЮ
   історія чіпляється до `method:Ns\Class::name`, до шляху заголовка,
   до таймкоду — до того, що переживає правки, на відміну від номера
   рядка

2  ЗБЕРІГАТИ СКОМПАКТОВАНИЙ КОНТЕКСТ, А НЕ ЛИСТУВАННЯ
   агенти й так стискають власний контекст, коли вікно закінчується.
   Цей скомпактований контекст і Є «чому» — уже написаний і вже стиснутий

3  ОБМЕЖУВАТИ ВІДПОВІДЬ ДО ТОГО, ЯК ЇЇ ПОБУДОВАНО
   кожен запит спершу оцінює власну вартість, потім застосовує політику:
   обрізати, спитати або пропустити і сказати
```

## Скільки коштує одне питання

Те саме питання, поставлене двома шляхами. Обидва файли справжні, обидва
виміряні.

| | звичайний файл (10.7 КБ) | великий файл (632 КБ) |
|---|---:|---:|
| комітів | 48 | 166 |
| `git log` | ≈ **11 700 ток** | ≈ **42 000 ток** |
| `git log -p` | ≈ **41 000 ток** | ≈ **240 000 ток** |
| **`cairn why --priority low`** | ≈ **384 ток** | ≈ **290 ток** |
| **`cairn why --priority normal`** | ≈ **1 660 ток** | ≈ **1 660 ток** |
| дешевше за `git log` | **×30** | **×146** |

Вартість Cairn **не росте разом з історією файла** — її тримає бюджет.
Файл із вдесятеро більшою історією коштує стільки само.

### На сесію, тиждень, квартал

Обидва множники нижче виміряні на 59 справжніх сесіях, а не взяті зі
стелі:

```text
різних файлів за сесію   медіана 21   (половина сесій 9–67)
сесій на тиждень         медіана 2, середнє 3.3
```

Як часто агентові справді потрібне «чому» — це судження, тому в таблиці
стоїть множник. Економія на звернення — зі звичайного файла
(11 700 → 384 токени):

| Звернень за сесію | За сесію | За тиждень | За квартал |
|---:|---:|---:|---:|
| 1 | 11 тис. | 23 тис. | 271 тис. |
| 3 | 34 тис. | 68 тис. | 814 тис. |
| 5 | 57 тис. | 113 тис. | 1.36 млн |
| 10 | 113 тис. | 226 тис. | 2.71 млн |

**Чим це не є:** рахунком. Заощаджені токени не перетворюються на гроші
один до одного, а агент, який ніколи не питав про історію, їх і не
витрачав. Що таблиця показує — це **вікно, яке ви повертаєте собі**:
контекст, що піде на задачу, а не на археологію.

## Кому що це дає

| | Без Cairn | З Cairn | Виміряно |
|---|---|---|---|
| **Розробнику** | читати код, потім `git log`, потім `git log -p` — 70–120 КБ на вузол | одна команда, причина саме цього методу | ×11–25; прибрана проза: 0 збігів у `git log`, ×22 через `-p` |
| **Агенту** | перечитує файли, пропонує відкочене | контекст попередніх сесій, із відомою наперед ціною | 0 % перевищень бюджету проти 87.5 % у схожого інструмента |
| **Проєкту** | «цей модуль якийсь проблемний» | лічильник переписувань на вузол; «багато правок, нуль задач» = латали наосліп | 26 правок, 4 на один дефект, 0 записаних причин |
| **Команді** | «спитай того, хто писав» — а він пішов | контекст переноситься копіюванням, зливається без дублів | merge 2 621 + 9 099 = 11 720; повтор додає 0 |
| **Компанії** | вартість контексту розмита по всіх задачах | та сама вартість, але виміряна, і знання, що переходить разом із проєктом | ×11–25 на звернення |

**Чого Cairn не робить.** Не замінює документацію, нічого не вирішує за
вас і не поверне нічого там, де агентських сесій не було — він
відновлює розмови, які відбулися.

## Виміряні результати

Повні таблиці, еталони й межі кожного виміру:
[`docs/MEASUREMENTS.md`](docs/MEASUREMENTS.md).

### Видобування вузлів

| Мова | Еталон | Файлів | Результат |
|---|---|---:|---|
| Python | `ast`, розбирач самої мови | 977 | **100.0 %** точного збігу (15 669 = 15 669) |
| Markdown | незалежний лічильник заголовків | 28 | **100.0 %** точного збігу (299 розділів) |
| PHP | індекс, побудований іншим інструментом, іншою мовою | 4 × 120 | повнота **88.7–93.9 %** |

Python дає 100 %, бо видобувач користується розбирачем самої мови. Це
правило, а не привід для гордості: власний сканер зʼявляється лише там,
де мова не дає нічого.

### Різнотипні активи

5 000 файлів PHP-моноліту й Python-застосунку:

```text
symbol   29.2 %   класи, методи, функції
whole    70.2 %   дані й бінарне — файл як один вузол
section   0.6 %   заголовки документів
```

Невідомий тип не є помилкою: він деградує до `whole:`. Із 797 PHP-файлів,
що туди потрапили, **0 %** мали оголошення — нічого не губиться мовчки.

### Сховище, приватність, переносність

```text
вхід        2.5 ГБ журналів · 1 088 файлів
сховище     7.2 МБ · 13 068 записів · 68 сесій · 119 скомпактованих контекстів
            2.32 МБ тексту ≈ 608 000 токенів стиснутої історії
баласт      96.6 % першої редакції були порожні рядки — відкинуто

редакція    418 збігів на живих даних, зокрема СПРАВЖНІЙ рядок
            підключення з паролем
ворота      100 % — 14 підробок із 14 спіймано,
            5 звичайних речень із 5 лишились недоторканими
містить     0 абсолютних шляхів · 0 згадок імені користувача

переносність копія теки дає ПОБАЙТОВО той самий вивід
```

## Будова

```text
cairn.py           єдина точка входу
core/              contract · store · paths · manifest · redact · budget
adapters/          збирачі журналів (+ навмисні підробки для воріт)
extract/           php · python · markdown · медіа-сайдкари
bind/              необовʼязковий зовнішній індекс символів
tests/             перелік обходу для кожного шару
```

### Модель вузла

| kind | unit | приклад адреси | що це |
|---|---|---|---|
| `symbol` | byte | `method:Ns\Class::name` | клас, метод, функція |
| `section` | byte | `section:Вступ/Межі` | заголовок і текст під ним |
| `segment` | second | `segment:00:04:12` | відрізок аудіо чи відео |
| `whole` | none | `whole:` | файл як один вузол |

Скрізь адресується **зміст, а не позиція**: символ, а не номер рядка;
шлях заголовка, а не номер розділу; таймкод, а не номер репліки.

### Переносність

```text
repo_id   відбиток НАБОРУ кореневих комітів — однаковий у будь-якому
          клоні, на будь-якій машині, у будь-якого акаунта
шляхи     лише відносні від кореня репозиторію
сховище   тека з JSONL; перенесення = копіювання; злиття = додати відсутнє
```

## Інтеграція

```text
рівень 0   CLI як є                 працює вже, ставити нічого не треба
рівень 1   скіл                     агент сам вирішує, КОЛИ спитати
рівень 2   плагін (хуки + скіл)     спрацьовує саме, перед правкою
```

Критерій — **хто ініціює виклик**: фіксована точка це хук, рішення
моделі це скіл. Покроково, разом із будовою плагіна й застереженнями:
[`docs/INTEGRATION.md`](docs/INTEGRATION.md).

### Підключити свого агента

Покладіть [`AGENT-ONBOARD.md`](AGENT-ONBOARD.md) туди, звідки ваш агент
читає правила — він підключить себе сам. Ворота перевірять результат:

```bash
python cairn.py selftest --store ./store --adapter _probe_empty    # exit 1
python cairn.py selftest --store ./store --adapter claude_code     # exit 0
```

Другий рядок обовʼязковий: без нього відхилення нічого не доводило б.

## Межі, названі чесно

```text
* сховище тримає ЛИШЕ скомпактовані контексти, не сире листування;
* перелік секретів скінченний: що не розпізнано, те не захищено;
* видобувач PHP — сканер оголошень, не парсер:
  повнота 88.7–93.9 %, виміряна, а не оцінена;
* репозиторій без сесій дає порожню відповідь, і це правильно:
  інструмент не вигадує того, чого не було;
* звʼязок «контекст → вузол» СЕСІЙНИЙ, а не причинний;
* журнали переживають репозиторії: індексуйте ДО видалення проєкту;
* формат журналів внутрішній для кожного агента й може змінитись —
  адаптер є зразком, не контрактом;
* самопідключення перевірено поки що на одному агенті.
```
