# Cairn

> [English](README.md) · [Для агентів](#для-агентів) · [Підтримати проєкт](#підтримати-проєкт) · [Apache-2.0](LICENSE)

### Агент змінює код. Cairn зберігає, чому це сталося.

Після нової сесії інший агент бачить код і коміти, але часто не знає,
чому попередню правку зробили саме так. Пояснення могло залишитися в чаті,
у стислій сесії або на іншому пристрої. Через це команда знову розбирає
ті самі рішення — або повторює стару помилку.

**Cairn збирає доступні докази в спільне сховище `.cairn`.** Він пов’язує
вузол проєкту, завершену правку агента, її мотив і Git-коміт. Перед новою
правкою агент може спитати: *«Як змінювався цей вузол і чому?»*

```text
розмова й намір → правка вузла → Git-коміт
        ↓              ↓             ↓
        └────────── .cairn ──────────┘ → історія для наступного агента
```

Читання файлів, `grep` і пошук не додають причинних подій. Незакомічена
правка лишається кандидатом. Коміт підтверджує участь правки лише тоді,
коли її перехід вмісту можна однозначно перевірити в Git.

## Що видно вже зараз

На репозиторії розробки Cairn **OpenCode, Claude Code і Codex** вимірювали
історію й поповнювали одне сховище даними своїх сесій. Зріз зроблено
**24 листопада 2026 року** на коміті `3159a6d`.

| Показник | Результат |
|---|---:|
| Git-коміти у сховищі | **40/40** |
| Коміти з підтвердженими правками сесій | **22** |
| Коміти лише з Git-контекстом | **18** |
| Унікальні правки, пов’язані з комітами | **184** |
| Перевірені зв’язки правок із комітами | **205/205**, 0 помилок |
| Події у `.cairn` і перевіреному приватному пакеті | **1 839/1 839** |
| Повний набір тестів | **37/37** |

Для контрольного `cairn_unified/why.py` збережено 78 кандидатів правок.
Із них 16 мають Git-свідка, 2 — причину конкретної події вузла, ще 2 —
причину стану файла. Решта 62 не мають однозначного зв’язку з комітом.
Так Cairn показує не лише пояснення, а й **де доказу бракує**.

Це пояснення учасників, пов’язані з перевіреними правками. Вони не
доводять, що рішення було правильним або хто саме виконав `git commit`.
Для старих комітів без журналу агентів Cairn не вигадує мотив.

## Для агентів

1. **Перед правкою** прочитай поточний код і запитай історію вузла через
   `why node`. Якщо сховище застаріло, спершу синхронізуй його.
2. **Після правки, до коміту** запиши коротко `why` і `intent` через
   `change note`. Codex може додати посилання на свій завершений
   `FileChange`; інші агенти записують лише те, що підтверджують їхні журнали.
3. **Після коміту** запусти синхронізацію. Cairn зв’яже правку з Git за
   унікальним переходом вмісту. Stash або discard не стають підтвердженою
   історією вузла.
4. **На іншому пристрої** перенеси приватний пакет подій і звір його перед
   імпортом. Він містить самі докази, а не посилання на локальні журнали.

Команди й правила доказу є в [мандаті агента](MANDATE-AGENT-CAIRN-CAUSAL-HISTORY.md).
[Підключення агента](AGENT-ONBOARD.md) описує CLI та MCP. Для роботи
потрібен Python; основний пакет не має зовнішніх runtime-залежностей.

## Межі релізу

Поточне дерево коду не містить машинних абсолютних шляхів. У 26 старих
комітах повної Git-історії вони ще є, тому цю історію не слід публікувати
без очищення й міграції Git-ідентичності Cairn. Для публікації підготовлено
чистий source snapshot без `.git` і `.cairn`. Приватний пакет зі словами
людини й агентів до нього не входить.
