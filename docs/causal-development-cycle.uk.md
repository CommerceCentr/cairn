# Причинний цикл розробки в Cairn

## Контракт запису

1. Агент читає код і `.cairn` без створення причинних подій. `grep`, відкриття файла та пошук вузла не є діями над вузлом.
2. Повідомлення людини фіксує намір у журналі сесії. Адаптер зберігає його ідентифікатор і час; зв'язок із правкою встановлюється лише за попереднім наміром у тій самій сесії.
3. Структуровані завершені `FileChange` Codex, `Write/Edit` Claude Code та відповідні події OpenCode стають кандидатами на мутацію. Shell-команди без структурованого запису не вгадуються. Codex `FileChange` доводить участь у файлі, але не в конкретній функції.
4. Після коміту збирач обмежує причинні події часом коміту, звіряє шляхи з його Git diff та записує `caused_by` тільки для підтверджених мутацій. Окремо Git створює `commit_fact --mutated--> node`. Видалення й перейменування зберігаються як статус Git; недоступні вузли потрапляють до `unresolved_mutations`.
5. `session --context_for_commit--> commit_fact` означає лише зв'язок сесії з комітом. Він не доводить, що сесія змінила кожен вузол коміту. Компактація сесії та детермінований витяг намірів прив'язуються через `derived_from`; компактація після коміту не стає його причиною.
   Коміт може бути створений в іншій, пізнішій сесії: для кожного попереднього журналу потрібно окремо прив'язати його підтверджені `FileChange`/`Edit` до того самого коміту. Для Claude Code `--after-commit <попередній-SHA> --strict-content` звіряє текст `Edit` з версіями файла до і після коміту.
   Для кожного текстового Git diff Cairn записує `commit_patch`: повні списки доданих і вилучених рядків, пов'язані з `commit_fact`. Вилучена проза лишається історичним свідченням; незакомічені правки до цього запису не входять.
6. `why` для файла збирає історію його індексованих вузлів і проходить від Git факту до контексту сесії. Якщо для вузла немає `caused_by`, відповідь прямо позначає наміри як контекст коміту, а не доведену причину правки цього вузла.

## Практичний виклик

Після створення коміту агент або інтеграція запускає `python tools/link_agent_session.py --root <спільний-корінь> --repo <репозиторій> --commit <повний-SHA> --source codex|claude_code --journal <журнал> --verify`. Для OpenCode використовується `causal_history.link`. Повторний виклик має ідемпотентні ключі. Вносити `.cairn` у спільну доставку слід через наявний federation export/import; Git репозиторій коду та журнал Cairn мають окремі ідентичності.

## Межі достовірності

- Зв'язок сесії з комітом задає явний виклик інтеграції, а не Git сам по собі. Потрібна перевірка, що обраний журнал належить агенту, який працював над комітом.
- `FileChange` не покриває правки через shell і не доводить конкретний символ усередині файла. Вони лишаються Git фактом без вигаданого автора дії.
- Історія, записана до цього контракту, не отримує нових ребер автоматично. Для неї потрібен окремий повторний імпорт із доступних журналів та Git.
- Портативні об'єкти Cairn містять прив'язки, витяг намірів і компактацію. Повне повторне звірення з сирим журналом після переносу потребує доступу до самого журналу на новому пристрої.
