# Codex і спільне сховище Cairn

Канонічний код: `Q:\prj\cairn`. Спільний проєкт Cairn: `Q:\prj\cairn-private\.cairn`. Адаптер журналу: `cairn_unified/adapters/codex.py`. Імпорт записує лише наміри, компактації, підтверджені Git-факти й доступні структуровані мутації. `read`, `grep`, пошук і перегляд не створюють причинних ребер. Зашифровану компактацію позначено без розкриття тексту.

## Читання й робота агента

Codex може викликати MCP сервер Cairn через stdio. Приклад локального запису в `config.toml` Codex:

```toml
[mcp_servers.cairn]
command = "python"
args = ["Q:/prj/cairn/tools/serve_shared_cairn.py", "Q:/prj/cairn-private"]
startup_timeout_sec = 30
```

Launcher завжди імпортує код із `Q:\prj\cairn`, навіть якщо Codex працює в іншому репозиторії. Корінь сховища передається явно. Перед підключенням перевірити `python -m cairn_unified --root Q:\prj\cairn-private project doctor` із публічного checkout. MCP-запити на читання не додають подій до журналу; інструменти запису додають їх за контрактом Cairn.

## Імпорт причинної хронології

Для сесії, достовірно повʼязаної з комітом:

```powershell
python Q:\prj\cairn\tools\link_agent_session.py `
  --root Q:\prj\cairn-private --repo <repo-path> --commit <sha> `
  --source codex --journal <rollout.jsonl> --verify
```

Параметр `--commit` означає реальний звʼязок сесії з цим комітом, який перевіряє оператор. Для OpenCode існує `causal_history.link`; для Claude Code цей самий `link_agent_session.py` приймає `--source claude_code`. Усі три джерела пишуть до одного проєкту Cairn. Якщо немає достовірного коміту, не запускати імпорт із випадковим SHA.

Шлях нестандартного каталогу журналів Codex для подальшої перевірки задає `CAIRN_CODEX_SESSION_ROOTS`. Значення може містити кілька тек через системний роздільник шляхів. Абсолютний шлях журналу не зберігається у переносному семантичному обʼєкті.

## Межа доказу

Git diff визначає, які вузли змінив коміт. Сесія Codex містить наміри користувача й компактації, але команди `exec` не дають надійної структурованої події правки. Тому Codex не отримує `node --caused_by--> session` лише на підставі тексту shell-команди; сесію можна знайти в області вузлів явно повʼязаного коміту, а Git-факт має ребро `mutated`. Для старого коміту або брудного робочого файла звʼязок знижується до адреси цілого файла.
